# 第0章 初识 Agent：这位实习生是谁

> "如果你只用过 ChatGPT 聊天，那你只见过 Agent 的'脑子'。这本书要带你见的，是脑子加上双手、笔记本、工作节奏、抗压能力之后的完整'实习生'。"

## 0.1 这本书写给谁

如果你符合下面的画像，这本书就是为你写的：

- 你写过 Python 或 Java，熟悉函数、类、模块这些概念
- 你用过 ChatGPT、Claude 或类似的 AI 聊天工具，觉得"挺厉害"
- 你听说过"Agent"这个词，但搞不清它和大模型有什么区别
- 你想搭建一个能自动完成任务的 AI 系统，但不知道从哪里下手
- 你看到网上各种 Agent 框架（LangChain、AutoGPT 等），想理解它们背后的设计原理，而不是只会调 API

**你不必要是 AI 专家。** 这本书假设你对大语言模型（LLM）只有最基本的认知——它接受文字输入、返回文字输出。除此之外的所有概念，我们都会从第一性原理讲起。

> 💡 **名词解释：LLM（Large Language Model，大语言模型）**
>
> 通俗地说：一位读过互联网上几乎所有公开书籍、文章和代码的"超级学霸"。你问他什么，他都能侃侃而谈，但他没法离开椅子去查今天的天气预报——他的知识停留在训练数据截止的那一天。
>
> 技术定义：一种基于 Transformer 架构的神经网络，通过海量文本数据预训练，学会预测下一个词的概率分布。GPT-4、Claude、文心一言、通义千问都属于 LLM。本书提到的"模型"如无特殊说明，均指 LLM。

**你最好有工程经验。** 因为我们会读真实的项目源代码（Python 和 TypeScript），会用伪代码讲解设计思路。如果你完全没写过代码，可能会觉得源码部分有点吃力——但业务概念部分仍然能读懂。

## 0.2 什么是 Agent？—— 从"实习生"说起

让我们从一个你熟悉的场景开始。

假设你是一家公司的部门主管，手下有一名**刚入职的实习生**。今天是他的第一天，你给了他一个任务：

> "帮我调研一下我们三个主要竞品的定价策略，整理成一份报告，下班前发我邮箱。"

这名实习生会怎么做？

他不会直接坐在工位上开始"思考"然后直接给你一份报告。他会经历一个完整的**工作流程**：

1. **理解任务**：他先确认——"三个主要竞品是哪三个？""报告需要什么格式？""定价策略是指官网标价还是实际成交价？"
2. **动手执行**：他打开浏览器搜索竞品官网，记录价格，查看产品文档，下载公开的价目表
3. **记录笔记**：他把搜到的信息记在笔记本上，避免等下忘记
4. **遇到问题**：他发现某个竞品的价格在官网上找不到，需要发邮件询问；或者他发现上午记的数据和下午看到的不一致，需要核实
5. **调整策略**：根据中间发现的新信息，他可能改变调研方向——"原来这家竞品不是按用户数收费，是按调用量收费，我得重新统计"
6. **完成任务**：整理笔记，写出报告，检查一遍有没有错别字和数据错误，发到你邮箱
7. **被打断时**：你中途路过他工位说"先别管第三家竞品了，重点看前两家"，他会记下这个指令，调整后续的工作重点

**这个完整的"理解→执行→记录→纠错→调整→完成"的工作流程，就是 Agent。**

> 💡 **名词解释：Agent（智能体）**
>
> 通俗地说：一位"有手有脚"的实习生。他不仅能听懂你的指令，还能自己查资料、记笔记、动手做事、遇到问题想办法——而不是只会坐在椅子上回答你的问题。
>
> 技术定义：以大语言模型为"大脑"，通过编排循环将"推理→工具调用→结果观察→再推理"这一过程反复推进，直到完成用户目标的自治系统。与单次 LLM 调用的根本区别在于：Agent 能把工具的执行结果回灌给模型，让模型基于真实世界的反馈决定下一步行动。

### Agent 和 LLM 的区别

现在把实习生换成**大语言模型（LLM）**，比如 GPT-4 或 Claude。

你同样说："帮我调研三个竞品的定价策略。"

LLM 的回应是：

> "根据公开信息，竞品 A 的定价是... 竞品 B 的定价是... 竞品 C 的定价是..."

看起来很智能，对吧？但这里有一个致命问题：**LLM 说的这些价格，是它训练数据里记住的，不是它今天刚去官网上查的。** 如果竞品昨天刚改了价格，LLM 不知道。如果某个竞品的价格根本不公开，LLM 会编造一个看似合理的价格给你。

**LLM 是一位"过目不忘但只能坐在椅子上的天才"**——他读过海量书籍，能言善辩，但无法打开浏览器、无法访问你的数据库、无法发邮件、无法操作文件。

**Agent 就是给这位天才配上了双手、双脚、笔记本和工作流程**，让他从"只能说的聪明人"变成"能干活的实习生"。

具体来说：

| 实习生的能力 | 对应 Agent 的模块 | 这本书的章节 |
|-----------|----------------|-----------|
| 接到任务后知道"先做什么、再做什么" | **编排循环** | 第1章 |
| 会用浏览器搜索、会发邮件、会操作 Excel | **工具系统** | 第2章 |
| 把事情记在笔记本上，下次还记得 | **记忆系统** | 第3章 |
| 理解领导的指令，拆解成可执行的步骤 | **Prompt 构建** | 第4章 |
| 整理数据，用清晰的格式写报告 | **输出解析** | 第5章 |
| 知道当前做到哪一步了，还剩多少没完成 | **状态管理** | 第6章 |
| 遇到网络断了、网站打不开，知道重试或换方法 | **错误处理** | 第7章 |
| 不会把所有搜到的信息都塞进脑子里，知道筛选重点 | **上下文管理** | 第8章 |
| 不会把公司机密数据发到公开网站，知道什么能做、什么不能 | **安全防护** | 第9章 |
| 写完报告后自己检查一遍有没有错 | **验证循环** | 第10章 |
| 任务太大时，知道请其他实习生帮忙分工 | **子 Agent 编排** | 第11章 |
| 第一天入职，知道去哪里领电脑、装什么软件 | **初始化与环境** | 第12章 |

这就是全书的核心线索：**我们不讲抽象的概念，我们讲一个实习生怎么干活。**

## 0.3 为什么需要 Agent？

你可能在想："我直接用 ChatGPT 不行吗？为什么要搞这么复杂？"

让我们看一个真实的例子。

假设你是一个后端开发工程师，接到一个任务："检查一下我们的用户服务代码，看看登录接口有没有 SQL 注入漏洞。"

### 方式一：用 ChatGPT（单次对话）

你把代码粘贴进去，问："这段代码有 SQL 注入漏洞吗？"

ChatGPT 回答："这段代码使用了参数化查询，看起来是安全的。"

好的，任务完成了？不一定。因为：
- ChatGPT 只能分析你贴进去的**这一段**代码，但 SQL 注入可能发生在用户服务调用的其他函数里
- 它不能真的运行代码去测试
- 它不能查看项目的依赖库版本，确认有没有已知漏洞
- 如果你还有 50 个接口要检查，你得重复这个流程 50 次

### 方式二：用 Agent（多轮自主执行）

你给一个 Agent 系统下达同样的指令。它会：

1. **读取项目结构**（工具：文件系统）—— 找到用户服务相关的所有代码文件
2. **逐个分析**（工具：代码分析）—— 对每个接口检查 SQL 注入风险
3. **运行测试**（工具：测试框架）—— 尝试构造注入攻击，验证是否真的安全
4. **查漏洞库**（工具：网络搜索/API）—— 检查依赖库是否有已知的 CVE 漏洞
5. **写报告**（工具：文件写入）—— 把发现的问题和修复建议写入 `security_report.md`
6. **通知你**（工具：邮件/消息）—— 报告完成后发消息告诉你

整个过程**不需要你手动干预**。你只需要发一条指令，Agent 像实习生一样自己推进，遇到障碍自己想办法，最后把成果交给你。

**这就是 Agent 的价值：把"需要人反复操作的多步骤任务"变成"发一条指令就能完成的自动化流程"。**

当然，Agent 不是万能的。它可能会犯错（就像实习生可能会记错数据），可能会陷入死循环（就像实习生可能会在一个网站上翻几十页找不到信息却停不下来），可能会误解你的指令（就像实习生可能把"定价策略"理解成了"营销策略"）。

**所以 Agent 系统的核心设计挑战就是：如何让这位"实习生"既自主又可靠？**

这正是我们要研究的内容。

## 0.4 我们要研究的四家"公司"

为了回答"如何让实习生既自主又可靠"这个问题，我们分析了四个真实的开源 Agent 项目。它们就像是四家不同风格的公司，培养实习生的方法各不相同。

### Hermes Agent（Python）—— 大型外包公司

Hermes Agent 的定位是**网关型 Agent**——它像一个大型外包公司，同时服务很多客户（多个用户会话）。它的特点是：

> 💡 **名词解释：网关型 Agent（Gateway Agent）**
>
> 通俗地说：一家咨询公司的前台。客户不是直接找某个顾问，而是先打到前台，前台根据客户需求分配给对应的顾问，同时负责计费、排队、打断等事务。
>
> 技术定义：在多用户场景下，Agent 系统作为一个中央入口（Gateway）接收请求，管理多个并发的用户会话，处理认证、限流、会话隔离等基础设施问题。Hermes Agent 和 OpenClaw 都属于这一类型。

- **预算控制极其严格**：每个任务都有"加班额度"，超支就必须停止
- **工具可以并行执行**：如果需要同时查三个竞品的价格，它会同时打开三个浏览器，而不是一个一个查
- **中断机制完善**：客户可以随时喊"停"，而且只停当前这一个任务，不影响其他客户

如果你要做一个**同时服务多个用户的 Agent 系统**，Hermes 的做法最值得参考。

### nanobot（Python）—— 个人工作室

nanobot 的定位是**个人助手**——它像一个自由职业者，只服务一个老板（单用户）。它的特点是：

- **极简设计**：核心循环只有 70 行代码，但功能完整
- **消息处理像流水线**：接到任务 → 执行 → 存笔记 → 交差，每一步都很清晰
- **错误不记笔记**：如果 API 调用失败了，它不会把错误信息写进笔记本（避免污染记忆）

如果你要做一个**简单的个人助手或聊天机器人**，nanobot 的简洁思路最值得学习。

### OpenClaw（TypeScript）—— 跨国集团

OpenClaw 的定位也是**网关型 Agent**，但它比 Hermes 更复杂。它像一个跨国集团，有完善的应急预案：

- **模型降级链**：如果主用的 AI 模型挂了，自动切换到备用模型
- **五层容错设计**：从单个请求的失败到整个进程的重启，每一层都有恢复策略
- **定时任务系统**：不仅能响应用户指令，还能像 cron 一样定时执行检查任务

> 💡 **名词解释：cron**
>
> 通俗地说：公司里的"定时闹钟"。每天早上 8 点自动发日报、每周五下午自动备份数据——不需要人手动去点，到时间就自动执行。
>
> 技术定义：类 Unix 系统中用于定时执行任务的后台服务。通过 crontab 配置文件定义"什么时候执行什么命令"，例如 `0 9 * * * /path/to/script.sh` 表示每天早上 9 点执行脚本。OpenClaw 内置了自己的 cron 调度器，让 Agent 可以在没有用户指令的情况下自主运行周期性任务。

如果你要做一个**7×24 小时运行的生产级 Agent 服务**，OpenClaw 的防御式设计是必修课。

### OpenCode（TypeScript）—— 设计工作室

OpenCode 的定位是**IDE 集成型 Agent**——它像一个和设计软件深度集成的工作室助理：

- **流式输出**：不是等全部想完再告诉你，而是一边想一边实时显示思路
- **死循环检测**：如果实习生反复做同一件无用的事（比如反复打开同一个网页），系统会自动发现并提醒
- **子任务内联执行**：大任务拆成小任务后，在主流程中直接完成，不需要额外调度

如果你要做一个**和具体工具（如 IDE、办公软件）深度集成的 Agent**，OpenCode 的流式设计和紧凑循环很有参考价值。

| 框架 | 语言 | 定位 | 适合学习的场景 |
|------|------|------|-------------|
| Hermes Agent | Python | CLI / 网关型 | 多用户并发、预算控制、工具并行 |
| nanobot | Python | 个人助手 | 极简设计、清晰的消息流、个人使用 |
| OpenClaw | TypeScript | 网关型 | 生产级容错、模型降级、定时任务 |
| OpenCode | TypeScript | IDE 集成 | 流式交互、死循环检测、工具集成 |

> 💡 **名词解释：CLI 与 IDE**
>
> **CLI（Command Line Interface，命令行界面）**：纯文本的交互方式。你在黑色窗口里输入命令，程序返回结果。没有图形界面，但自动化和脚本化最方便。Hermes Agent 主要工作在命令行里。
>
> **IDE（Integrated Development Environment，集成开发环境）**：程序员写代码的工具，如 VS Code、IntelliJ IDEA。OpenCode 不是独立的程序，而是作为插件嵌入到 IDE 中，在你写代码时随时提供 AI 辅助。
>
> 简单理解：CLI 是"打字对话"，IDE 是"在编辑器里工作"。

## 0.5 如何阅读这本书

### 三部分结构

全书分为三个部分，对应实习生成长的三个阶段：

**第一部分：Agent 的骨架（第1-5章）**

这是实习生刚入职时必须掌握的基本功。没有这些，实习生连"怎么干活"都不知道。

- 第1章：工作节奏（编排循环）—— 实习生接到任务后，怎么一步一步推进
- 第2章：双手（工具系统）—— 实习生能使用哪些工具（搜索、发邮件、操作文件）
- 第3章：笔记本（记忆系统）—— 实习生怎么记笔记，下次还能想起来
- 第4章：理解任务（Prompt 构建）—— 实习生怎么听懂你的指令，拆解成可执行步骤
- 第5章：汇报成果（输出解析）—— 实习生怎么把零散的信息整理成结构化的报告

**第二部分：Agent 的韧性（第6-9章）**

实习生光会干活不够，还得可靠——遇到问题时不能崩溃，犯错时不能搞砸整个项目。

- 第6章：工作台（状态管理）—— 实习生怎么知道自己现在做到哪一步了
- 第7章：抗压与纠错（错误处理）—— 实习生遇到 API 超时、网站打不开时怎么办
- 第8章：注意力分配（上下文管理）—— 实习生怎么在信息爆炸时抓住重点
- 第9章：职业底线（安全防护）—— 实习生不会把公司机密数据发到公开网站

**第三部分：Agent 的进阶（第10-12章）**

优秀的实习生不仅能独立完成任务，还能自我检查、团队协作。

- 第10章：自我检查（验证循环）—— 实习生交稿前自己检查一遍
- 第11章：团队协作（子 Agent 编排）—— 任务太大时，实习生知道请同事帮忙
- 第12章：入职第一天（初始化与环境）—— 实习生上班第一天需要准备什么

### 每章的结构

每章都遵循统一的七节结构：

1. **开篇故事** — 用实习生的具体场景引入本章主题
2. **业务概念** — 这个模块在 Agent 系统中到底是什么
3. **必要设计** — 所有 Agent 都必须有的"底线"设计
4. **四个项目的实现对比** — Hermes、nanobot、OpenClaw、OpenCode 分别怎么实现（含源码）
5. **独特高价值设计** — 每个项目最值得借鉴的闪光点
6. **设计思想总结** — 如果我要自己搭 Agent，这部分的设计 checklist 是什么
7. **本章小结** — 用实习生口吻做一句总结

### 阅读建议

- **如果你是新手，建议按顺序读。** 每章都建立在前面章节的基础上，比如不理解"编排循环"（第1章），就很难理解"状态管理"（第6章）。
- **如果你只想快速了解某个模块，可以直接跳到对应章节。** 每章都是相对自包含的，开篇会简要回顾前置知识。
- **源码部分可以选读。** 如果你目前只想理解概念，可以跳过源码对比部分；如果你想动手搭建，源码部分是核心参考。

## 0.6 实习生成长路线图

让我们用一个完整的实习生工作场景，预览全书的脉络。

> 早上 9:00，实习生小李入职。IT 部门给他配了一台电脑、装了必要的软件、开通了邮箱账号（第12章：初始化与环境）。
>
> 9:30，主管给了他第一个任务："调研三个竞品的定价策略，下午 5 点给我报告。" 小李拿出笔记本，把任务要点记下来（第3章：记忆系统），然后问清楚了"竞品是哪三家""报告格式是什么"（第4章：Prompt 构建）。
>
> 10:00，小李开始干活。他打开浏览器搜索竞品 A 的官网（第2章：工具系统），记录价格，再搜竞品 B、竞品 C。每查到一个价格，他就记在笔记本上。查完一轮后，他发现竞品 B 的价格在官网上找不到，需要发邮件询问——于是他切换工具，写了封邮件（第1章：编排循环——任务推进的节奏）。
>
> 11:00，笔记本上的信息越来越多，小李开始筛选重点。他知道主管只关心"按用户数收费还是按调用量收费"，于是把注意力集中在这一点上，忽略其他无关信息（第8章：上下文管理）。
>
> 12:00，竞品 B 的邮件回复了，但价格表是一个 PDF 附件。小李下载下来，用 PDF 阅读器打开，提取关键数据（第2章：工具系统——文件处理）。
>
> 14:00，小李发现竞品 A 的官网打不开了。他没有傻等，而是换了搜索引擎，在百度快照里找到了缓存页面（第7章：错误处理——遇到障碍时换方法）。
>
> 15:00，小李开始整理报告。他把笔记本上的零散信息按照"竞品名称-定价模式-单价-备注"的格式填入表格（第5章：输出解析），写完后自己检查了一遍：数据有没有记错？格式对不对？有没有漏掉某个竞品？（第10章：验证循环）。
>
> 16:30，主管路过说："竞品 C 不用看了，重点看 A 和 B 的对比。" 小李在笔记本上标注这个变更，调整报告结构（第6章：状态管理——应对任务变更）。
>
> 17:00，报告发到主管邮箱。整个过程中，小李没有向主管透露任何公司内部信息，也没有把搜索记录发到公开论坛（第9章：安全防护）。
>
> 下午 5:30，主管又给了个更大的任务："下周我们要上线新功能，你负责写技术方案、设计接口、写测试用例。" 小李评估了一下，这一个人干不完，于是请另外两个实习生分别负责接口设计和测试用例，自己主抓技术方案，最后汇总（第11章：子 Agent 编排）。

**这就是 Agent 系统要模拟的完整能力。** 从理解任务、调用工具、记录记忆、管理状态，到处理错误、保障安全、验证结果、协作分工——每一个环节都是本书的一章。
